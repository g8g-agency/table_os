# Product Specification Document

## Orderlly Admin Backend API & Database Specification

### Version

1.0

### Product

Orderlly Restaurant Management Platform

### Component

Admin Backend (Node.js + Express + PostgreSQL + Supabase)

---

# Purpose

The Admin Backend provides secure APIs and business logic for restaurant owners and managers to manage every aspect of the restaurant. It handles authentication, authorization, validation, business rules, database operations, audit logging, and integrations with all platform modules.

# Authentication APIs

### Login

```
POST /api/v1/auth/login
```

Expected

* Validate credentials
* Generate JWT
* Return access token
* Return refresh token
* Return user profile

Validation

* Invalid email
* Invalid password
* Locked account
* Expired account
* Disabled account

---

### Logout

```
POST /api/v1/auth/logout
```

Expected

* Revoke session
* Invalidate refresh token

---

### Refresh Token

```
POST /api/v1/auth/refresh
```

Expected

* Generate new access token

---

# Acceptance Criteria

The Admin Backend is considered production-ready when:

* Authentication works correctly.
* RBAC is enforced on every endpoint.
* Tenant and branch isolation are verified.
* All CRUD APIs pass validation.
* Database integrity is maintained.
* Realtime events function correctly.
* Audit logs are generated.
* Response times meet performance targets.
* Security best practices are implemented.
* No critical or high-severity backend defects remain.
